Start here — what counts as “right”?

  1. Check the answer key first. Read the PDF page text and required quote. Is this genuinely enough to answer the question? These are assistant-authored draft labels, not unquestionable truth.
  2. Follow the quote: PDF text → filtered Docling items → stored chunks → retrieved top five. The first place it disappears identifies the earliest observable failure.
  3. Check the automatic match. Same document, matching page range, and the entire quote must occur after Unicode/case/whitespace normalization. This is a conservative text check, NOT semantic understanding. Equivalent wording or a quote split across chunks can be a false negative.
  4. Read the generated answer yourself. Faithfulness = supported by supplied context; correctness = factually right against the source/key; completeness = covers required facts; citation support = each citation actually supports its claim. Citation presence alone proves none of these.
  5. Record your decision below and export it. 0 = major failure/unsupported; 1 = partial/minor issue; 2 = fully meets criterion. Leave blank if not reviewed. Explain the specific claim/evidence in your notes.

This is a single text-transcribed PDF pilot, not a test of original diagram/OCR understanding. PDF native text is only an inspection aid: check the real PDF for layout/relationship disputes. No answer-quality score here is automatically proven. Review records do not modify the golden dataset or overwrite the original results.

Baseline metrics — recomputed and checked


Hit@k: at least one required evidence group found. Evidence recall@5: fraction of required groups found. Complete@5: all groups found. MRR@5: reciprocal rank of the first matching chunk (zero if none). Each table cell is the arithmetic mean of per-question scores; recall is macro-averaged, not pooled across groups.


These metrics do not prove that the LLM answered correctly. Database round-trip checks validate saved text/vector consistency, not whether embeddings understand meaning. Token overlap ignores order and relationships.
